Supabase Row Level Security (RLS) Configuration

Supabase enables Row Level Security (RLS) on newly created tables by default. If your inserts or updates fail with code 42501, simply run the following SQL script in your Supabase SQL Editor. 

-- 1. Enable RLS and permissive policies for 'product'
ALTER TABLE public.product ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Public can view products" ON public.product FOR SELECT TO anon, authenticated USING (true);
CREATE POLICY "Public can insert products" ON public.product FOR INSERT TO anon, authenticated WITH CHECK (true);
CREATE POLICY "Public can update products" ON public.product FOR UPDATE TO anon, authenticated USING (true);
CREATE POLICY "Public can delete products" ON public.product FOR DELETE TO anon, authenticated USING (true);

-- 2. Enable RLS and permissive policies for 'order_table'
ALTER TABLE public.order_table ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Public can view orders" ON public.order_table FOR SELECT TO anon, authenticated USING (true);
CREATE POLICY "Public can place orders" ON public.order_table FOR INSERT TO anon, authenticated WITH CHECK (true);
CREATE POLICY "Public can update orders" ON public.order_table FOR UPDATE TO anon, authenticated USING (true);
CREATE POLICY "Public can delete orders" ON public.order_table FOR DELETE TO anon, authenticated USING (true);
💡 Pro-Tip for Schema Architecture:

In your schema, product_id is marked as the Primary Key of order_table. In a production store, you usually want each customer order to have its own unique id so that multiple customers can purchase the same product without a primary key collision. You can adjust this in the Supabase Table Editor if you desire unlimited orders per product.
